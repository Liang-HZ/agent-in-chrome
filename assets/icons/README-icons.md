# 图标出图规则

出图脚本与商店展示图放在这里（`assets/icons/`），**不在 `extension/` 里**：
打商店包是把整个 `extension/` 目录 `cpSync` 进上传包的，凡是运行时用不到的
文件都会被一起打进 zip。256 只用于商店页展示，那是在后台单独上传的，不该占上传包的体积。
运行时真正要用的 PNG（16/24/32/48/64/128）和 SVG 源文件仍在 `extension/icons/`。

Chrome 的 manifest 图标**只认 PNG**（SVG 只有 Firefox 支持），所以 SVG 是源文件，
上架用的是各尺寸单独导出的 PNG。

## 为什么不能从 128 缩下去
1. 缩放是降采样：投影和白线会被抹平，16px 上直接糊掉。
2. Retina（2×）屏上 Chrome 给 16px 槽位要的是 **32px 位图**、给 24px 槽位要 48px；
   字典里缺整倍数尺寸它就拿别的尺寸拉伸——这是「看起来糊」最常见的真正原因。
   所以尺寸表补到了 16 / 24 / 32 / 48 / 64 / 128（256 只给商店展示，不进 manifest）。

## 每档都在自己的像素网格上取整

viewBox 一律 128，所以 1 物理像素 = 128 ÷ 尺寸 个单位：16px→8u，24px→5.333u，
32px→4u，48px→2.667u，64px→2u。**方块的四条边、半环的圆心和线宽都必须落在整像素上**，
否则边缘会出现半透明的鬼影带——这是上一版 16px 看着糊的直接原因（方块的 y=6 h=116
在 16px 上映射到 0.75…15.25px，上下各留了一条 25% 透明度的边）。

| 尺寸 | 方块 | 填充 | 高光 | 投影 | 圆心 | 半径 | 线宽 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 16 | 0,0,128,128（满幅） | 纯色 | 无 | 无 | 56,56 = 7px | 24 = 3px | 16 = 2px |
| 24 | 满幅 | 纯色 | 无 | 无 | 53.333 = 10px | 26.667 = 5px | 16 = 3px |
| 32 | 满幅 | 纯色 | 无 | 无 | 56,56 = 14px | 28 = 7px | 12 = 3px |
| 48 | 满幅 | 渐变 | 有 | 无 | 56,58.667 = 21,22px | 32 = 12px | 10.667 = 4px |
| 64 | 满幅 | 渐变 | 有 | 无 | 56,58 = 28,29px | 32 = 16px | 12 = 6px |
| 128 / 256 | 4,10,120,108 | 渐变 | 有 | 有 | 56,58 | 32 | 14 |

小尺寸满幅 + 纯色是刻意的：投影要留边、渐变和高光在 16px 上只贡献噪点，
而满幅的四条边全部落在整像素上，边缘最锐。

## sw.js 也要补
按状态换图标那处（约 6515 行）的 path 字典要和 manifest 一致，补上 24 与 64：

```js
    await chrome.action.setIcon({
      path: {
        16: `icons/icon-${key}-16.png`,
        24: `icons/icon-${key}-24.png`,
        32: `icons/icon-${key}-32.png`,
        48: `icons/icon-${key}-48.png`,
        64: `icons/icon-${key}-64.png`,
        128: `icons/icon-${key}-128.png`,
      },
```
