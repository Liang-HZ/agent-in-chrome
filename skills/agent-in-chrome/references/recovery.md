# 中断恢复与排查

## 多步任务断了

网络闪断、元素不见了、页面重渲染、对话被压缩——先 `browser_trace`。它是唯一记着"跑到第几步、哪一步断的、当时在哪个页面"的地方;`browser_status` 只有现状没有历史。

正确接法:trace 判断断之前哪些事**已做成** → `browser_read_page` 看页面**现在**的状态 → 从当前状态往下走。`currentPage` 是现在的实测页面,每一步的 `url` 是那一步执行时的页面,两者可能不同。提交类步骤做没做成拿不准时,去页面找证据(订单号、成功提示、那条请求的状态码)或问用户,别猜。

看历史会话:`browser_trace { list: true }` 列出本机最近的 trace,`{ session: "<name 或 session id>" }` 读某一个;`session` 和 `step` 同给就直接取那个会话的那一步(不会退回整份清单)。

trace 里凭据按字段名打码,`browser_type` 输入的文本只记长度。边界:用 `eval` / `cdp` 主动把 `document.cookie` 读成普通字段,trace 认不出那是凭据。

## 排查表

| 现象 | 处理 |
|---|---|
| 浏览器没连上 | `browser_status` 看状态;确认 Chrome 在跑、扩展启用;装完 native host 不用重启 Chrome(每次 connectNative 现读配置),等它自己拨号重连(30 秒一次,空闲时退避到最长 2 分钟),或让用户点扩展弹窗的「立即重连」 |
| 操作超时 | 多半页面弹了 alert / confirm 卡住,`browser_handle_dialog` 处理掉;或标签页已被关 |
| 找不到某个按钮 | 多半被 `maxElements` 截掉而非不存在:看 `elementsTotal`,用 `container` 或 `find` |
| 点了"成功"页面没反应 | 看 `verified`:`"hit"` 确认打中,`"navigated"` 是这一下把页面带走了,`"moved"` / `"unknown"` 是**验不了**(页面挪过、校验监听器装不上、或点完那一帧被换掉),**不等于打中,也不等于没打中**——真打歪会直接报错;坐标点击没有这道校验,换 `ref` / `selector` |
| 接管报"浏览器内部页面" | `chrome://`、扩展页、商店页挂不了调试器,换页面 |
| 报"别的扩展注入的框架挂不上调试器" | 密码管理器在密码框 / 卡号框上弹的浮层,Chrome 因此拒绝给整个标签页挂调试器。工具层已试过两级恢复(撤焦点、摘浮层宿主),**重试不会好**;标签组已标 🙋,在对话里请用户在那一页关掉浮层再试;每次都撞就请他在该站点停用那个扩展 |
| 报"与主会话的连接断开" | 持有桥接的会话刚退出,几秒内自动接管,重试即可 |

`browser_reload_extension` 仅在 `AGENT_IN_CHROME_DEV=1` 起 server 时注册,只给开发这个扩展本身用;它会让所有会话的页被释放。
