它在你电脑上动了什么

全部摊开讲：写到哪些文件、要哪些权限、什么时候联网、哪些内容它读不到。

想看你机器上的真实绝对路径？终端跑 npx @liang-hz/agent-in-chrome check， 它会打印本机实际解析出的每个路径、权限位、以及连接令牌是否就位（不会打印令牌本身）。

它在你本机写什么

八处，全部在你的 home 目录和 agent 自己的配置里。

位置内容保留
~/.agent-in-chrome/运行时代码副本、启动脚本卸载时删除
~/.agent-in-chrome/token本机连接令牌（0600）。没有它的本地进程连不上你的浏览器卸载时删除
~/.agent-in-chrome/traces/操作留痕：每步工具名、打码后入参、当时页面 URL 与标题40 会话 / 7 天
~/.agent-in-chrome/screenshots/agent 要求的截图最近 100 张
~/.agent-in-chrome/cookies/你显式要求导出的 cookie（目录 0700、文件 0600）不自动清理
~/.agent-in-chrome/*.log连接日志（不含页面内容）不自动清理
各浏览器 NativeMessagingHosts/一份 host 注册清单 …卸载时删除
你的 agent 的 MCP 配置一条 server 注册（写前自动备份原文件）卸载时移除
cookie 导出是明文凭据
只有你（或你让 agent）显式调用 browser_cookies_export 才会产生，用途是把登录态搬到另一个浏览器实例。默认只把文件路径返回给模型，不返回明文。用完请自己删掉那个文件——它不会自动过期。

扩展权限逐条

manifest 里申请的每一项，以及它到底用来干什么。

debugger
核心机制：通过 Chrome 调试协议读页面、发可信输入事件。接管期间页面顶部有关不掉的提示条，这是 Chrome 的安全设计。
nativeMessaging
与本机 MCP server 之间的唯一通道。
tabs / tabGroups
列标签页；把 agent 开的页收进可见的彩色标签组。
scripting
页面快照与元素定位的注入式管线。
storage
会话-标签页归属表（浏览器会话存储，关浏览器即清）。
alarms
service worker 被回收后自动拉起重连。
<all_urls>
agent 要能操作你指定的任意站点；去哪由你的指令决定。

网络出站

产品自身不向任何服务器发送数据：没有遥测、没有统计、没有崩溃上报，全部是本机进程间通信。唯一例外是版本更新检查（向 npm 查询最新版本号），不携带任何本机信息，设 AGENT_IN_CHROME_NO_UPDATE_NOTIFIER=1 可关闭。agent 访问哪些网页，完全由你的指令决定。

哪些东西读不到

  • 密码框、信用卡号、CVV、短信验证码的值不会出现在任何页面读取结果里，只报「已填写（N 字符）」。
  • 操作留痕里输入的文本只记长度；Cookie、Authorization、token、api key 等字段一律打码。

如实告知的边界：打码认的是「字段名像凭据」。agent 主动执行 JS 把 document.cookie 读进普通变量时，打码认不出来。
